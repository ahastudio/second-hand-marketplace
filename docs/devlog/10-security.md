# 10. 보안 검토와 강화

- 날짜: 2026-10-15
- 범위: 인증·API·프론트·컨테이너·배포 설정의 보안 검토와 수정
- 장치 목록, 찾은 방법, 반복 방법, 남은 위험은 [04-SECURITY.md](../04-SECURITY.md)에 정리했다.

## 진행 방식

1. **찾기**: 코드 리뷰(OWASP Top 10·ASVS 기준), Trivy 이미지·시크릿 스캔, `npm audit`, 강화한 이미지를 로컬에서 실제로 기동해 `curl`과 로그로 확인, 전체 테스트 재실행.
2. **Red**: 항목마다 `SecurityHardeningTest`를 먼저 작성해 실패를 확인했다(9개 중 7개 Red).
3. **Green**: 구현 후 모든 테스트 통과.
4. **반복 가능하게**: 같은 점검을 `scripts/security-scan.sh` 한 번으로 다시 돌릴 수 있게 했다.

## 주요 변경

- 비밀번호를 Argon2id로 교체(기존 BCrypt 해시는 로그인 시 자동 업그레이드).
- 이메일 단위 로그인 잠금(5회 실패 → 10분, 429), 없는 이메일도 해시 검증을 수행해 응답 시간 차이 제거, 이메일 소문자 정규화.
- JWT 비밀값 기본값 제거와 32바이트 미만 기동 실패, 발급자 검증.
- API 보안 헤더, 프론트 Nginx CSP 등 보안 헤더.
- 오류 응답 비노출, Spring이 로그에 남기던 임의 기본 사용자 비밀번호 제거.
- 검색어 LIKE 와일드카드 이스케이프·길이 제한.
- 컨테이너 읽기 전용·capability 제거·`no-new-privileges`, 게시 주소 제한 옵션.
- 설정을 `application.yml` 하나로 통합(환경 값은 환경변수).
- 의존성 패치(Alpine, Tomcat, Jackson, BouncyCastle).

## 배운 것

- **새 의존성이 새 취약점을 가져온다**: Argon2용으로 추가한 BouncyCastle 1.82가 스캔에서 치명적 2·높음 2건으로 걸려 1.85로 올렸다. 라이브러리를 추가하면 스캔을 다시 돌린다.
- **E2E 테스트가 회귀를 잡았다**: CORS 도입 후 개발 환경의 상태 변경 요청(POST/PUT/PATCH/DELETE)이 403이 됐다. Vite의 문자열 프록시가 Host를 바꿔 같은 출처 요청이 교차 출처로 판정된 탓이며 `changeOrigin: false`로 해결했다.
- **로그를 읽어야 보이는 문제가 있다**: 쓰지 않는 기본 사용자의 임의 비밀번호가 로그에 찍히고 있었다.

## 검증

- `scripts/security-scan.sh`: `npm audit` 0건, 백엔드·프론트 이미지 Trivy 0건, 시크릿 스캔 0건, 보안 테스트 통과.
- 로컬 운영 설정 기동: 비루트 실행, 읽기 전용 파일시스템, 응답 헤더, CORS 허용 200 / 비허용 403, 로그인 6번째 실패 429, DB 해시가 Argon2id 형식.
- JWT 비밀값이 없거나 짧으면 기동에 실패함을 확인.
- 서버 재배포 후 같은 항목(비루트, 읽기 전용, 보안 헤더, CORS)을 서버에서 확인.
