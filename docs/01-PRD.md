# PRD: 중고거래 플랫폼 MVP

- 상태: v1.0 — MVP 구현 완료, 코드와 동기화됨 (2026-10-14)
- 관련 문서: [02-SPEC.md](02-SPEC.md)(구현 명세), [03-PLAN.md](03-PLAN.md)(진행 계획·결과), [04-SECURITY.md](04-SECURITY.md)(보안)

## 1. 배경과 목적

개인 간 중고 물품을 올리고 찾아볼 수 있는 가장 작은 형태의 거래 플랫폼을 만든다.
목적은 두 가지다.

1. 판매자가 물품을 등록하고 관리하며, 구매자가 탐색할 수 있는 핵심 흐름을 검증한다.
2. Outside-in TDD(E2E 테스트 → API → 단위)로 개발하는 프로세스를 실습하고 문서로 남긴다.

## 2. 대상 사용자

| 역할 | 설명 |
| --- | --- |
| 판매자 | 로그인 후 물품을 등록/수정/삭제하고 판매 상태를 바꾼다 |
| 구매자 | 로그인 없이도 목록/상세를 볼 수 있다 (연락·채팅은 범위 밖) |

## 3. MVP 범위 (In Scope)

- F1. 회원가입 / 로그인 / 로그아웃 (로그아웃은 클라이언트에서 토큰을 폐기)
- F2. 상품 등록 (제목, 설명, 가격)
- F3. 상품 목록 조회 (최신순, 제목 키워드 검색, 상태 필터는 제외. API는 페이지네이션 지원, UI는 첫 20개)
- F4. 상품 상세 조회
- F5. 상품 수정 / 삭제 (본인 상품만)
- F6. 판매 상태 변경 (판매중 / 예약중 / 판매완료, 자유 전이)

## 4. 범위 밖 (Out of Scope)

이미지 업로드, 채팅/메시지, 결제, 찜, 카테고리, 위치 기반 검색, 신고, 관리자, 소셜 로그인, 페이지네이션 UI 고도화, 자동 CI/CD.

## 5. 사용자 스토리 & 수용 기준

- F1: 사용자는 이메일/비밀번호로 가입하고 로그인할 수 있다. 중복 이메일, 잘못된 비밀번호는 오류 메시지를 본다.
- F2: 로그인한 사용자는 제목·설명·가격을 입력해 상품을 등록하고, 등록 후 상세 페이지로 이동한다. 비로그인 시 로그인 페이지로 이동한다.
- F3: 누구나 최신순 목록을 본다. 검색어를 입력하면 제목에 포함된 상품만 보인다. 결과가 없으면 빈 상태 문구를 본다.
- F4: 누구나 상품 상세(제목/설명/가격/상태/판매자/등록일)를 본다. 없는 상품은 "찾을 수 없음"을 본다.
- F5: 판매자 본인만 수정/삭제 버튼이 보이고 동작한다. 타인의 상품은 API에서 403.
- F6: 판매자는 상태를 바꾸고, 목록/상세에 즉시 반영된다.

## 6. 비기능 요구사항

- 단일 인스턴스, 로컬 실행(Docker Compose로 PostgreSQL) 및 수동 서버 배포(Ansible + Docker Compose).
- 비밀번호는 Argon2id 해시로 저장. 인증은 JWT(Bearer) 사용. 보안 요구와 점검 방법은 [04-SECURITY.md](04-SECURITY.md).
- API 응답 시간은 로컬 기준 체감 지연 없음(성능 목표 수치는 두지 않음).
- 모든 기능은 Playwright E2E 테스트 시나리오로 검증된다.

## 7. 성공 기준

- F1~F6 각각에 대응하는 Playwright E2E 테스트가 통과한다.
- `docker compose up -d postgres` + 백엔드/프론트 실행만으로 전체 시나리오가 재현된다. (README 참고)
- 서버 배포 시 프론트 `25800`, 백엔드 `25801`로 접속하고 DB 포트는 외부에 노출되지 않는다.
- 단계별 devlog가 `docs/devlog/`에 남아 있다.

## 10. 범위 해석 메모

- F1 "로그아웃"은 서버 세션이 없으므로 토큰 폐기(클라이언트)만 수행한다. 서버 측 토큰 폐기는 범위 밖.
- F3의 "페이지네이션 UI 고도화"는 범위 밖이라 UI는 첫 20개만 보여준다.
- 수용 기준 F5의 "타인의 상품은 API에서 403"은 백엔드 테스트로, "버튼이 보이지 않음"은 E2E 테스트로 각각 검증한다.
